## 🏗 Featured Work

### 🔋 Industrial IoT Battery Monitoring Platform
> `Java` · `Spring Boot` · `GCP Cloud Run` · `Cloud SQL` · `MQTT` · `ESP32` · `SAP ERP` · `React / TypeScript` · `Docker` · `GitHub Actions`

End-to-end IoT monitoring system for industrial battery fleets at HOPPECKE Batteries. ESP32 edge sensors publish telemetry over MQTT → ingested by Spring Boot microservices on GCP Cloud Run → persisted in Cloud SQL → surfaced in a real-time React/TypeScript dashboard → synced bidirectionally with SAP ERP.

**Problem solved:** Replaced manual battery health checks with continuous anomaly detection, cutting operational response time from hours to minutes and eliminating unplanned downtime across the fleet.

---

### ⚙️ [Spring Boot + Camunda BPM Workflow Engine](https://github.com/yaseenshar/springboot-camunda)
> `Java` · `Spring Boot` · `Camunda BPMN` · `REST API`

BPMN-driven process automation integrated with Spring Boot. Covers process deployment, lifecycle task management, and REST API exposure for workflow orchestration — mirroring patterns used in enterprise ERP and financial systems.

**Problem solved:** Decouples business process logic from application code, making complex workflows auditable, versioned, and modifiable without redeployment.

---

### 📦 [Delivery & Payment Microservice API](https://github.com/yaseenshar/delivery-payment-api)
> `Java` · `Spring Boot` · `PostgreSQL` · `REST`

Production-style REST API for delivery and payment operations. Implements clean layered architecture, DTO mapping, and transactional consistency — built as a reference for enterprise-grade Spring Boot service design.

**Problem solved:** Provides a reusable, maintainable service template that handles the transactional complexity of coordinating delivery state with payment processing.

---

### 🧩 [Microservices Reference Architecture](https://github.com/yaseenshar/microservices)
> `Java` · `Spring Boot` · `Docker`

Multi-service Spring Boot architecture demonstrating independent deployability, inter-service communication, and Docker-based service composition. A working reference for teams migrating from monolith to microservices.

**Problem solved:** Gives teams a concrete starting point for microservices decomposition — showing the seam between services before over-engineering with a service mesh.
